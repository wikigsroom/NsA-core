# NsA Core v0.4.0

2026-11-07 · Asia/Taipei · [English README](../../README.md) · [中文 README](../../README.zh-CN.md)

## 中文版本说明

本版将基于 nx2android/nxnative 的统一 Android 游戏大厅、内容制作/服务流程、开发约束和完整实拍文档固定为首个 NsA Core 版本。目标流程为：用户安装已配置 App，在列表发现支持的游戏，下载并准备资源，然后在同一 App 本机游玩。

### 交付物

- 标签源码：统一 Android 大厅、原生接入、内容制作、目录服务、worker、运营网页、规范与测试。
- Windows x64 与 macOS 桌面制作工具：由对应系统 CI 从本标签构建，架构以附件名为准。
- 完整中英 README、玩家/开发/部署手册、文档索引及实机截图、录屏和 GIF，随工具包一同提供。
- `SHA256SUMS.txt` 与 `release-manifest.json`：真实附件大小、SHA-256 和源码提交；发布前回读附件确认。

当前内部双游戏 APK 含本地配置与商业游戏模块，不作为公开附件。本版不包含商业游戏程序、密钥、玩家存档或已部署的公共目录。源码可按文档构建无需商业输入的原创 2048 演示；面向普通玩家的分发仍需运营方配置真实服务、签名信任和获准交付的内容。

### 主要功能

- 暗色 Obsidian 默认竖屏大厅；发现、搜索/筛选、详情、游戏库、下载和设置。游戏实际运行才横屏，退出返回竖屏。
- 持久下载队列、用户意图、8 MiB 检查点、Range/ETag/分块与完整摘要校验、授权续签。
- 签名清单、完整文件索引、ZIP64 流式准备、安全路径校验与日志驱动激活/恢复。
- 同 APK 内明确选择的原生运行模块、实际编译身份核对、独立 SONAME、新游戏进程和认证握手。
- 按游戏隔离存档与设置，带摘要备份、兼容检查、替换前备份与可恢复导入交换。
- 目录/策略/兼容服务、真实上传、worker 回读校验、独立审核、运营网站与审计。

### 本次关键修正与文档变化

### 使用与升级

## English release notes

This first NsA Core release fixes a versioned source/tool distribution for the unified Android game hall built on nx2android/nxnative. The intended player flow is install a configured app → find a supported game → download/prepare → play locally in the same app.

### Distribution

Tagged source includes the Android hall/runtime integration, content tools, catalogue API, worker, operations site, constraints and tests. Windows x64 and macOS authoring archives are built on their respective CI runners from this tag. Both contain the English/Chinese README, player/development/deployment guides, complete tracked documentation and reviewed real-device gameplay media.

`SHA256SUMS.txt` and `release-manifest.json` identify actual asset sizes, hashes and source revision. CI inspects both archives, uploads to a draft and verifies downloaded bytes before publishing a normal release.

The private two-game APK contains local provisioning and commercial game modules and is not attached. No commercial game program, key, personal save or hosted public catalogue is distributed. The documented source setup builds the original open-source 2048 without commercial inputs. General-player distribution requires an operator's service, signing/trust and approved content.

### Features and changes

- Dark Obsidian portrait discovery, search/filtering, details, library, downloads and settings; landscape only at actual game runtime.
- Persistent single-transfer scheduling, user intent, verified 8 MiB checkpoints, Range/ETag/block/full-hash checks and scoped grant renewal.
- Signed manifests, complete file indexes, safe ZIP64 streaming, staged activation and journal-backed recovery.
- Explicit compiled native slots, actual ELF/SONAME checks, isolated fresh game process and authenticated session handshake.
- Per-game saves/settings, hashed exports, compatibility checking, backup before replacement and recoverable import swaps.
- Real upload/read-back/worker verification, independent publication review, catalogue/policy/capability services and staff audit.
- UTF-8 Unicode dependency handling and mandatory rebuilding on missing inputs; stale compiled identity rejection at collection and packaging.
- Lease-backed stopped-session reconciliation after hall loss; serialized recovery/launch and guarded malformed/stale reconnect context.
- Complete replacement of both old root README bodies and upstream games table with NsA documentation.
- New actual BotW movement PNG/GIF/MP4 and reload capture, plus current 2048/library media. Historical captures keep their own identities.
- Full tracked documentation in desktop archives and a tag-driven, read-back-verified two-platform release pipeline.

### Validation and upgrade

The phone candidate uses Android source `5c1bff0`, APK `3bd6c8…3451d`, with byte-identical native libraries from `d427f08`. Build/package checks passed, 26 JVM tests freshly passed, lint reports 0 errors/16 warnings, and all 22 USB instrumentation tests passed. Overlay and instrumentation preserved all 22 existing player files.

Original 2048 completed real input, changed save, normal portrait return and byte/16-tile-identical fresh-process reload. BotW 1.9.0 completed scene loading, a new manual save and fresh-process reload. A retake confirmed visible touch movement. Android reclaimed main for low memory during that retake; normal game exit rebuilt the hall, which directly opened a new game process and reloaded all three matching committed manual-slot files without a manual hall restart. Controlled kill attempts and the interrupted original retake remain retained rather than relabeled as passes.

Device: Motorola edge plus, Android 12/API 31, Snapdragon 865/Adreno 650, arm64, 4096-byte pages. Earlier five switching rounds and audio-signal checks belong to the previous `5808f5…6d06` APK. See the [execution record](../hall/session-recovery-round-2026-11-07.md).

Release/document checks ran 135 Python cases: 96 passed, 39 skipped, including four public-asset integrity/exclusion cases. All eight contract groups passed. Validation checked 50 Markdown documents, 846 local links, 52 media artifacts, 40 provenance records and hashes for 199 current private evidence files; video decoding passed. Skips are not passes.

Use the matching desktop archive's `INSTALL.md`, or follow [development](../development.md) for the source-based Android demo. Configure real providers as described in [deployment](../deployment.md). Existing internal Android users must normally exit first, export important saves and overlay with the same package/signature; do not uninstall/clear data to bypass mismatches. Changed runtime/content identities need a new immutable release. Repository version `0.4.0` and internal app `0.1.0-dev` are distinct version domains.

### Known limits

BotW remains experimental, with earlier short shrine observations around 7–13 FPS and graphics fidelity limitations. Full G0, controlled authenticated reconnect while a game survives main-only termination, representative continuous 30-minute performance/game speed/temperature, subjective/BotW audio, physical power-loss/ENOSPC and broader/16 KiB-page devices are not accepted. No public catalogue or release-signed hall APK is deployed. Silent clips cannot demonstrate sound quality. This formal GitHub release does not change those acceptance boundaries.
