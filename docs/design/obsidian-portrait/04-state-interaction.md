# 04 · 状态、按钮与关键交互

## 1. 状态分别表达

| 维度 | 事实 | 界面责任 |
| --- | --- | --- |
| 目录与发行 | 可见、内测、下架、版本撤回、访问资格 | 能否展示/取得该版本 |
| 本机支持 | 已验证、实验、未验证、不支持、需更新模块 | 能否正式下载和运行，以及原因 |
| 下载任务 | 排队、传输、用户暂停、等待网络、系统暂停、空间不足、失败、取消、文件已下载 | 显示真实网络阶段与可信字节 |
| 安装 | 未安装、暂存、校验、准备、有效、损坏 | 是否已有可启动的有效安装 |
| 游戏会话 | 未运行、检查、启动、运行、退出、异常结束 | 是否可新建/返回当前会话，方向如何切换 |
| 存档 | 无记录、已提交、备份中、导入中、不兼容、恢复中 | 能否安全导出/覆盖与如何解释进度 |

这些维度不能互相覆盖。例如“下载 100%”不能覆盖“安装未准备”，更新包下载不能抹掉旧有效版，服务器下架不能伪装成删除本地存档。列表、详情、下载中心、通知和我的游戏读取同一事实来源。

## 2. 主操作的判定优先级

先核验当前版本的访问/故障阻断与必要支持条件，再看会话、有效安装、任务和可下载状态。主按钮只指向一个真实可执行动作；不能靠改按钮文字来伪造准备完成。

| 情形 | 主按钮 | 次操作 / 必须说明 |
| --- | --- | --- |
| 当前版本故障阻断 | 查看修复 / 更新游戏 | 明确阻断原因，不显示普通开始 |
| 本机不支持 | 查看本机可玩游戏 | 显示缺少条件，不先下载大包 |
| 缺少新内容所需模块 | 更新 App | 已有旧版是否仍能玩，按旧版依赖和撤回事实单独判断 |
| 实验或未验证 | 查看限制 / 进入允许的实验流程 | 与正式推荐分开，不标“已验证可玩” |
| 同一游戏正在运行 | 返回游戏 | 不新建第二会话 |
| 另一游戏正在运行 | 先结束当前游戏 | 明确提示未保存风险，不直接覆盖原生全局状态 |
| 已安装但关键资源损坏 | 检查与修复 | 保留存档和可恢复的旧版 |
| 安装有效、无会话 | 开始游戏 / 继续游戏 | 有已提交记录才表达“继续”；并不承诺内存快照 |
| 排队中 | 查看下载任务 | 可取消；不显示开始 |
| 传输中 | 查看进度 / 暂停 | 有实际字节与总量时才显示百分比 |
| 用户暂停 | 继续下载 | 保留进度与暂停原因 |
| 等待非计费网络 | 等待 Wi-Fi / 更改本次网络选择 | 计费网络必须明确确认 |
| 系统停止任务 | 继续下载 | 表达需用户继续，不承诺后台永远常驻 |
| 下载空间不足 | 管理空间 | 显示额外缺口；清理后重新复检 |
| 下载失败 | 重试 | 分类网络、服务、对象变化和资格问题 |
| 下载完成、正在校验 | 正在校验 | 不能开始，进入 S06 查看阶段 |
| 校验通过、正在准备 | 准备中 | 可测进度才显示数值；保持竖屏 |
| 准备完成、登记有效 | 开始游戏 | 此时才允许启动检查 |
| 未安装且条件满足 | 下载游戏 | 确认版本、大小、峰值空间与网络 |
| 有更新且旧版仍有效 | 继续当前版本 | 更新为明确次动作，不能静默破坏旧版 |

“继续游戏”表示启动对应游戏并使用其最近已提交存档。实际游戏若需要在自己的菜单选择继续，保留游戏正常流程。

## 3. 下载与安装操作

下载链路：`queued → fetching_manifest → transferring → verifying_download → downloaded`。暂停、等待网络、等待空间、系统暂停、失败都保留明确原因和已验证分段。安装另有 `staging → verifying_files → prepared → ready`。

用户点击下载后：检查可见资格、设备、模块、版本和空间→打开确认层→确认网络→创建唯一任务。二次点击、通知操作和重建后恢复均复用相同任务；不能重复写出第二套大资源。

暂停只暂停可暂停的传输，按钮在请求中显示“正在暂停”。取消需确认影响范围，清理仅属于该任务且无引用的临时文件，不删除安装、旧版或存档。重试先验证对象和可信分段；发行对象变化时不拼接旧字节。

校验、解包和登记阶段不继续显示网络速度。提交临界阶段不承诺立即中断；可将取消标记为“正在完成当前步骤”，保留回下载中心的入口。失败恢复使用实际提交日志，不把被中断的半成品显示为可玩。

下载完成提示的文案为“下载完成，正在校验与准备”，就绪提示为“已准备好，可以开始游戏”。首版默认手动开始，后台完成不拉起游戏、不改变方向。

进入游戏后，其他资源下载和安装重任务默认在安全边界暂停，明确显示“游戏运行期间已暂停”；退出后按网络和用户偏好恢复。不能把这种暂停写成“你已暂停”，也不能覆盖用户此前主动暂停或等待网络的原因。实际安装提交临界区由任务协调层提供安全暂停点。

## 4. 空间与单位

容量明确使用 GiB/MiB；速度 MiB/s；底层按 64 位字节计算。用户要看“下载量、安装后、当前可用、还需空间”，不要求理解目录和压缩算法。

```text
additional_required = 下载尚需分配 + 安装尚需写入 + 准备尚需空间 + 安全余量
```

旧版已经占用的空间不再从当前可用量里重复扣除。更新保留旧有效版；仅经确认可释放的数据计入清理收益。真实包量和余量采用发布数据，示例不变成固定阈值。

| 本轮虚构样例 | 值 |
| --- | --- |
| 星环漫游首次下载 | 10.0 GiB 下载 + 15.0 GiB 安装 + 1.0 GiB 准备 + 2.0 GiB 余量 = 28.0 GiB |
| 首次下载情境可用 | 42.4 GiB |
| 参考首页已下载 | 6.4 / 10.0 GiB，64%；可用变为 36.0 GiB |
| 该阶段额外需分配 | 3.6 + 15.0 + 1.0 + 2.0 = 21.6 GiB |
| 参考设备总量/已用/可用 | 128.0 / 92.0 / 36.0 GiB |

参考占用细分为游戏资源 25.0、下载文件 6.4、缓存 2.0、存档及备份 0.2、系统其他 58.4 GiB，合计 92.0。单条存档大小是其中的一部分。不同情境切换在原型外的审阅控制中完成；不能把两种情境当成同一时刻的设备实测。

## 5. 启动与返回

点击开始时记录来源页面、选择与滚动位置，检查有效安装和匹配模块。S08 的检查与可取消准备保持竖屏；转入本次游戏实际运行界面时才请求横屏。原生窗口和输入使用切换后的真实尺寸，并以同一会话身份协调，禁止方向变化引起重复启动。

正常退出前说明未保存内容可能丢失，等待正常退出与已提交存档落盘的事件；大厅恢复竖屏及来源状态。取消、加载超时、崩溃和系统回收都有独立恢复原因。无法证明完整保存时，不显示“进度全部保存”。

恢复大厅不依赖它一直留在内存；任务、安装和会话来源应可持久化重建。切后台时声音、画面和输入按已验证策略暂停/挂起，恢复失败时重新启动并读取已提交档，不承诺即时快照。

## 6. 存档和破坏性操作

| 操作 | 确认前显示 | 成功条件 | 失败/取消 |
| --- | --- | --- | --- |
| 清理缓存 | 可清范围，说明缓存可重建且保留存档 | 实际可释放数据清理完成 | 不改安装或存档，报告真实结果 |
| 删除游戏资源 | 游戏、版本、预计可释放量、默认保留存档 | 任务/引用检查通过并删除相应资源 | 运行中禁止删活动版；保留存档 |
| 导出存档 | 最近已提交记录，导出位置由用户选 | 一致快照写入系统选定位置并确认完成 | 取消选择器无副作用，失败不删原档 |
| 导入备份 | 身份/版本/日期/覆盖范围/现状备份 | 预检、备份、可恢复替换及登记通过 | 不兼容禁导；中断保留现有档及备份 |
| 内容更新 | 新旧版本、空间、存档兼容及旧版可用性 | 新版有效登记且满足健康/回退条件 | 不偷偷删除唯一可用版 |
| App 更新 | 版本、大小、更新说明 | 交系统安装确认并由安装后版本事实验证 | 拒绝或失败保留旧 App |

“删除存档”必须是独立的明确行为，不放在默认勾选项中，也不随“清缓存/删游戏”顺手执行。原型不会实际读写存档，系统选择器和数据事务由原生阶段验证。

## 7. 消息与错误层级

有内容的页面优先用内联提示，保留用户上下文；没有可用缓存时才用全页错误。短提示表达一次操作结果，不能成为唯一长期错误说明。确认层承载影响和决定，不能堆叠成多层弹窗。

错误必须包含发生了什么、已保留什么和能执行的下一步。自动重试只适用技术方案允许的短暂网络故障，有限次数；完整性错误、资格问题、故障阻断和存档不兼容不能无限重试。普通界面不展示堆栈、密钥路径、编译参数或 GPU 环境变量。
