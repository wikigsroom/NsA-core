# 07 · 研发交付、数据契约与验收

## 1. 设计基线与优先关系

本轮固定方案 1 = D · 曜黑极简。暗色、手机非游戏默认竖屏、进入实际游戏后横屏、退出恢复竖屏均为用户已确定要求。视觉令牌、页面规格和状态规则作为同一版本交付，后续变更记录受影响的页面、组件和需求编号。

信息与交互冲突时以产品需求和状态规则为准；尺寸/颜色以令牌和规范原型为准。生成视觉用于方向和美术参考，图内不同字距、头像、图标或 AI 自动添加的细节不构成新需求。正式 Android 页面重建为真实文字、矢量与原生控件。

## 2. 各层交付责任

| 层 | 要交付的内容 | 与设计连接 |
| --- | --- | --- |
| Android 大厅 | Compose 页面、导航、安全区、权限、文件选择器、偏好、状态订阅 | S00–S08、S12–S31；本轮 HTML 只为设计审阅 |
| 任务与安装 | 唯一任务、真实字节、可靠暂停恢复、校验/准备/登记、空间复检 | S04–S06、S14、S26、S31 |
| 原生会话 | 本次启动身份、模块、运行事件、横屏窗口、暂停、退出/异常、存档提交 | S08–S12、S17；不能因大厅重建结束全部进程 |
| 本地数据 | 安装、任务、偏好、已提交记录、版本和来源状态 | 跨页面一致并可在进程回收后恢复 |
| 服务与运营 | 目录、资格、模块依赖、兼容证据、不可变包、问题受理、版本撤回 | 以受控状态驱动玩家页面，运营动作不混入主导航 |

## 3. 页面展示模型

下表是页面语义展示模型，camelCase 名称不是线上字段。实际 DTO、数据库记录、状态和接口已在 [技术约束 v2.0](../../engineering/README.md) 与 [机器契约](../../engineering/contracts/README.md) 冻结；页面的生产瞬态另见 [交互验收规格](../../product/页面与交互验收规格.md)。所有 ID 来自受信任状态，页面不拼服务器文件路径，也不把展示文字当业务状态。

| 模型 | 最低必要字段 | 展示约束 |
| --- | --- | --- |
| GameSummary | gameId、名称、封面引用、类型、可见发行 | 名称与主操作必须对应同一身份 |
| Compatibility | releaseId、App/模块/驱动/设备范围、分级、原因、证据摘要 | 无证据显示未验证，不默认可玩 |
| ReleaseDetail | 版本、语言、输入、已知限制、传输/安装/工作字节 | 未知值明确显示，不能造估计量 |
| TransferTask | taskId、game/release、阶段、可信/总字节、速率、原因、可执行操作 | 同一事实映射到详情、任务卡和通知 |
| InstallRecord | active/pendingRelease、READY/校验、实际占用、损坏原因 | downloaded 不等于 ready |
| RuntimeSession | sessionId、game/release/module、阶段、来源页面、错误 | 一次一个会话；运行界面决定横屏 |
| SaveSummary | gameId、兼容版本、最近提交、大小、备份、占用锁 | 只有已提交记录才被称为已保存 |
| StorageSnapshot | 总量/可用、资源/临时/缓存/存档/其他、采集时间 | 缺口实时复检，旧版不重复扣除 |
| NavigationRestore | 标签、路由、选择、滚动、查询/筛选、会话来源 | 返回或重建恢复真实位置和数据 |

UI 使用一个统一的可执行操作模型，例如下载/暂停/恢复/修复/开始/返回当前会话。多维事实计算后再出按钮，不在 32 个页面分别复制判断。控制层接到重复动作应幂等，忙碌按钮仅作为额外防护。

## 4. 界面事件与恢复

| 事件 | 触发 | 结果 |
| --- | --- | --- |
| openGame | 封面/任务详情 | 读取指定 game/release，保持竖屏 |
| requestDownload | 详情主动作 | 检查条件并显示 S04 |
| confirmDownload | 用户明确确认 | 建立或复用任务 ID |
| pause/resume/cancelTask | 任务卡/通知 | 控制同一任务，返回实际结果 |
| downloadVerified | 文件与身份通过 | 进入安装，不能立刻改成可玩 |
| installReady | 有效安装登记通过 | 允许开始入口 |
| requestLaunch | 开始/继续 | 记录来源并复检，S08 竖屏 |
| runtimeEntered | 本次运行界面交接 | 切到游戏横屏边界 |
| saveCommitted | 游戏提交完成 | 更新已保存记录；UI 不自造成功 |
| runtimeExited / runtimeFailed | 退出/异常 | 恢复竖屏来源，显示实际原因 |
| export/importResult | 系统选择器与存档事务 | 成功后提示，失败保留原数据 |
| appInstallResult | 系统安装/再次启动版本 | 实际确认更新结果，拒绝仍可继续使用旧版 |

这些是端侧行为契约，不等于同名事件都必须上传。诊断附加、遥测范围和保留时间遵循已确认隐私选择；用户未选择的存档、原始内容和密钥不发送。

## 5. 实施顺序

1. 固定主题、原生系统栏/安全区、四入口和返回行为，落地 C01–C12。
2. 目录、搜索、详情与统一按钮模型；接入真实支持和发行数据。
3. 下载确认、任务、安装准备和空间恢复；做到传输 100% 仍不能提前启动。
4. 游戏库、管理、存储、备份和修复；删除与覆盖按事务保护数据。
5. 启动协调、独立游戏进程、真实横屏窗口与退出恢复；验证两个真实内容切换。
6. 设置、权限、问题反馈、App/内容更新、关于与许可，完成字体/读屏/手柄和故障回归。

对应原计划重点为 T-05、T-07、T-09–T-16、T-19；T-02–T-04、T-08、T-17–T-18 等提供依赖。保持 [已有开发计划](../../product/开发计划与验收矩阵.md) 的 G0/G1 退出条件，不把 HTML 原型当成统一 APK 闭环。

本轮包含 Markdown 规格、机器可读令牌/页面目录/样例、可离线打开的原型、32 张规范截图、8 张新关键视觉及原始选定首页、生成与检查记录。源码与必要设计资产统一提交到 NsA-core；原始出图、浏览器临时配置和检查中间产物保留在忽略的 output 目录。
