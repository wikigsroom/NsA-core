# 06 · 无障碍、适配与性能

## 1. 触控和操作

Android 控件触控区域以至少 48×48dp 为基线，视觉图标可更小，周围区域参与点击。相邻独立控件留出通常不少于 8dp 的间隔；不能把删除/继续挤在一条无区分的小文字上。依据：[Android 默认无障碍行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。

关键动作有可见按钮，不能只靠滑动、长按、拖拽或悬停。长列表里的更多菜单有明确可访问名，破坏性动作二次确认。按下反馈不改变布局大小，加载中防重复请求。

## 2. 文字与对比

本项目采用普通文字至少 4.5:1、重要非文本边界/焦点至少 3:1 的设计检查目标；这不自动构成完整 WCAG 或原生无障碍认证。文字基准参考：[W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。计算结果随令牌记录在 [检查报告](10-review-report.md)。

文字跟随系统缩放。重点检查 100%、130%、200%；内容区域增长和滚动，不能通过缩小字体、锁缩放、剪掉标签来“通过”。标题优先换行；游戏列表允许受控省略，但详情和可访问名称提供完整名称。

大字体时首页三小卡改纵向行，两列目录必要时改一列，定义行从左右改上下。底部入口可换行并增高；主按钮、错误原因和最后一个可操作项不能被固定栏遮挡。状态栏占位不代表应用接管系统字体。

## 3. 读屏、键盘与手柄

| 对象 | 语义与顺序 |
| --- | --- |
| 页面标题 | 进入新页先定位标题，之后按视觉顺序读取 |
| 装饰图标 | 邻近已有同义文本时不重复朗读 |
| 单独图标按钮 | 明确动作名，如“返回”“清除搜索”“暂停下载星环漫游” |
| 游戏卡 | 名称、安装/支持状态及动作合并表达；不逐段重复封面名称 |
| 底部导航 | 读出标签、当前选中和未完成任务数 |
| 进度 | 读出阶段、可信数值及暂停原因；不每个字节抢读 |
| 表单 | 标签、是否可选、错误和帮助有关联；错误后保留输入 |
| 弹层 | 隔离背景交互，焦点在层内循环，关闭恢复来源控件 |
| 短提示 | 合适的状态播报，不强抢当前输入焦点 |

键盘/手柄的焦点顺序与视觉一致，焦点外框与选择状态分别表达。不能因滚动后焦点不可见继续触发隐藏按钮。物理手柄断开释放旧按键并允许回触屏；不把手柄当成声明触屏可玩的必要条件。

浏览器原型只检查可见焦点、部分键盘行为与语义结构；Android TalkBack、Switch Access、实际手柄、IME 和系统返回需要 USB 真机单独验证。

## 4. 窗口、安全区与方向

主设计尺寸是逻辑宽度，不能把生成图片像素或 393×852 原型尺寸照搬为固定 dp。顶部和底部由真实窗口安全区驱动，键盘弹出时输入和提交仍可见；列表底部为导航/CTA 保留完整空间。系统栏由系统绘制，应用使用 inset 处理遮挡。依据：[Android WindowInsets](https://developer.android.com/develop/ui/compose/system/insets)。

| 条件 | 适配行为 |
| --- | --- |
| 360dp 小手机 | 16dp 边距，保持目标尺寸；正文可滚动，不塞桌面三列 |
| 393/412dp 手机 | 标准主卡、两列目录、三张其他游戏小卡 |
| 字体 200% | 列表与按钮纵向增长，卡片降列、信息行上下排列 |
| 600dp 以上窗口 | 主体居中限宽，保留竖屏信息层级；不把手机卡片无限拉宽 |
| 折叠/分屏/系统强制宽窗口 | 继续可操作并保存状态；不依赖固定宽高或强制重启 |
| 游戏横屏 | 游戏窗口、暂停、退出确认使用运行层尺寸和安全区 |
| 返回/失败/取消 | 回竖屏大厅，恢复来源、选择、任务和页面位置 |

平台对大屏方向约束存在明确规则：Android 16 对目标 API 36 的部分大屏窗口忽略方向/可调整大小限制，同时列有游戏等例外。具体应用分类与设备组合需实现时核验；手机产品默认竖屏的设计要求保持不变。依据：[Android 16 大屏自适应行为](https://developer.android.com/about/versions/16/behavior-changes-16#adaptive-layouts)。不采用伪造类别或改变系统设置来代替适配。

## 5. 动效与渲染成本

遵循系统减少动态效果与应用偏好。去掉循环装饰、自动轮播和大幅位移；状态仍以文字和必要进度表达。原型检查了浏览器减少动态模式，不能由此推导原生动画已经通过。

封面按显示尺寸加载，列表滚出后可回收；游戏进入前释放不必要的大图和后台动画。长目录使用适合原生的惰性列表和分页，禁止一次把完整资源目录读入 UI。当前设备游戏性能有限，大厅采用纯色、轻量矢量和简单边界，不增加实时模糊与全屏背景动画。

性能目标继续采用产品需求的测量口径，原型不是性能测试包。低内存、后台下载、温控、30 分钟真游戏与低帧率专项均需真实设备证据。
