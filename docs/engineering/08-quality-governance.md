# 08 · 测试、验收、变更与开发约束

基线 v2.0 · 2026-11-06。适用于人类开发者、自动化工具和后续代理。详细用例仍以 [24 项计划与 58 个验收案例](../product/开发计划与验收矩阵.md) 为索引，本章规定证据和放行方式。本轮文档校验不计为 App、服务或游戏验收通过。

## 1. 文档约束与变更

先服从用户指示和适用 AGENTS；产品行为由主 PRD、360 条细则、32 页交互规格共同定义，工程实现由本套章节和机器契约定义，视觉由已选 D · 曜黑极简 tokens/页面规格定义。各文档按职责互补；有冲突先定位对应需求、保留证据并修正文档，不能利用旧稿里“建议”一词绕开 v2.0 的必须项。

工程默认值见 [defaults.json](../product/data/defaults.json)，允许按 ADR/CR 修改但必须同步消费者、测试和说明。品牌、正式渠道、首发内容、正式参考设备、范围、地区和预算见 DEC-01～09；未决事项不阻止无依赖的研发，但不得把它们写成已获批准或已部署。

| 变更类型 | 必需记录 | 同步内容 |
| --- | --- | --- |
| 用户行为/范围 | CR，问题/目标/受影响需求/替代方案/验收/责任人/日期 | PRD、细则、页面、计划、必要设计 |
| 架构/选型/默认值 | ADR，背景/决定/代价/兼容窗口/回退/证据 | 技术章、defaults、锁文件、相关验收 |
| HTTP/数据/原生 ABI | 契约版本评估，消费者矩阵、迁移/回滚方案 | Schema/OpenAPI/header、生成模型、前后端、负例与示例 |
| 视觉 | token/组件/页面差异和对比证据 | 已选设计源与实际 UI；不偷偷换成另一方案 |
| 内容/模块 | 新 release/build/slot，兼容与存档关系 | 清单、注册表、证据、许可与发布审核 |

新增字段优先可选兼容；必需字段、新含义、枚举闭集改变、存档格式或 ABI 布局改变都不能声称“只是小改”。保留已发布消费者的兼容窗口；API v1 不兼容改动另开版本或明确协商。版本升高不能抵消丢存档、越权、半包启动等硬性约束。

## 2. 开始与完成条件

开始一个工作项前，开发者需能指出：T-ID、需求与细则 ID、页面/典型状态/补充 INT、输入数据契约、异常与返回路径、前置依赖、待决策是否真正阻塞，以及完成证据。不得以原型一个按钮存在推定后端已有能力。

完成条件同时包括：相应实现、合适验证、真实状态与恢复行为、数据/版本兼容、文案/无障碍、受控日志和文档同步；需要设备/服务证据却未执行时标记未验收而非关闭。低影响可逆文案/样式修改无需编写镜像测试；状态转换、完整性、安装、IPC、迁移与存档必须有能检出破坏的测试。

PR 描述写清具体触发、改变后的行为、需求/细则关联、验证和剩余限制。不得夹带无关 Vulkan 真机实验、用户未提交修改、游戏文件或凭据。提交到 `wikigsroom/NsA-core`，保留原上游归属；已授权的可逆研发持续推进，不人为增加重复许可步骤。

## 3. 测试层次

| 层次 | 需要检出的问题 | 证据边界 |
| --- | --- | --- |
| 契约静态校验 | Schema/OpenAPI/本地引用、需求映射、样例、签名向量、状态枚举不一致 | 只证明规范内部可检查，不能证明服务已实现 |
| 领域单元测试 | 动作优先级、多重 blocker、幂等、字节溢出、合法/非法状态边 | 不依赖 UI 截图猜业务状态 |
| 文件/数据库集成 | 大包流式传输、分段复用、journal 恢复、迁移、save swap | 使用自造测试数据，不需要提交商业游戏 |
| HTTP/后台集成 | 范围隔离、角色矩阵、ETag、过期/续签、审核/签名/作业失败 | API 实测响应，不能只通过 OpenAPI 文档 |
| Android UI/系统 | 32 页与 INT、竖横切换、通知/权限/SAF、返回、进程重建 | Windows 原生工具 + USB 真机；不使用模拟器 |
| 多游戏运行 | 同 APK 两模块、A/B 独立数据、退出/崩溃/输入/声音、实际读档 | 必须是真游戏，不以视频或测试页面替代 |
| 发布与运营 | 新装/升级、线上对象读回、精确撤回、备份恢复、许可与隐私 | 受控候选环境，不默认公开发布 |

依赖版本固定，测试结果记录 commit/构建、设备条件和时间。通过后不无理由反复扩大测试；有新改动、失败或未解决风险时再补充。不得为了显示绿色把未连接的设备用例改成成功。

## 4. 必需故障注入矩阵

| 主题 | 至少注入点 | 必须保持 |
| --- | --- | --- |
| 网络 | 首请求/段中/段末；206 错区间、非零 200、416、URL 到期、ETag 变、429/5xx、弱网/计费切换 | 不拼异物；暂停意图不丢；有界重试 |
| 检查点 | 数据写后、fsync 后、hash 后、DB 前/后、可信尾后 | 不把未验证字节算完成；重启对账 |
| 解包 | 路径穿越、链接/重复、超大展开、索引缺/多文件、单文件错 hash、磁盘写满 | 只影响专属 staging，旧版/存档完好 |
| 安装 | CREATED/EXTRACTED/VERIFIED/目录发布/DB 激活/清理每边界 | 重建后只有完整版本可启动 |
| 更新 | 旧会话运行、新版准备/激活、新版首启失败、旧模块缺失、存档不兼容 | 固定会话版本，不静默损坏存档或删唯一旧版 |
| 会话 | 重复点击、双 game 并发、迟到授权/首帧、乱序/重复事件、Binder 死亡、native _exit、Surface 先于模块、退出卡住 | 单会话；大厅存活/可重建；不自动再启动 |
| 存档 | 正在提交、导出取消、错游戏导入、超限、备份失败、交换每边界进程结束 | 最近完整提交可恢复；不覆盖活会话的档 |
| 系统 | 进程回收、重启、锁屏、音频焦点、权限拒绝、FGS/UIDT 停止、系统文件选择器晚回调 | 不无限保活；恢复实际状态与导航 |
| 服务 | 两管理员冲突、自己审核、对象只上传一半、签名失败、worker 重放、outbox 重放、范围到期 | 未审核不公开；审计与发布一致；不可重复产生版本 |
| 数据 | 旧库升级、迁移失败、孤立目录、伪 READY、策略回放、超过 2^53/Long 上限数值 | 不破坏性清库、不执行未知内容、不精度截断 |

需要断电耐久性承诺时除进程终止还要在专用测试机做安全受控的系统/电源中断验证；不能用 kill 进程证明所有存储设备断电语义。手机/资料未经明确授权不做破坏性重置或卸载，仅使用专门测试安装验证卸载行为。

## 5. 视觉与交互验收

使用已定稿 32 页、73 个命名典型状态、26 个组件和 [补充 INT-01～10](../product/页面与交互验收规格.md)。73 是设计稿列出的典型组合，不是允许忽略加载、校验、取消、系统结果等瞬态。画面正确和功能正确分别检查。

手机大厅始终竖屏；只有 runtime 边界及暂停/退出游戏层横屏；从运行打开常规设置按源会话挂起→竖屏设置→恢复同一会话，不新建游戏。启动检查/图形准备竖屏，进入具体运行页才横屏；失败/取消回原页面、滚动位置、筛选和任务上下文。

基准覆盖 360/390/430dp 常见手机宽度，系统字体 100/130/200%，手势/三键导航、长中文标题、IME 和读屏。关键目标 ≥48dp，安全区、正文对比、非颜色状态、焦点顺序、禁用原因与确认动作可识别。最少在一台真实手机验证；平板/折叠如未测明确未验证，不宣称覆盖。

## 6. 性能测量口径

数值是首版工程验收默认目标，见 [defaults.json](../product/data/defaults.json)，不是已经达到的性能或商业 SLA。无法达到先记录结果、优化或经 CR 改支持范围，不能删掉失败样本。

| 指标 | 测量范围与门槛 |
| --- | --- |
| 缓存冷启动 | 进程未运行、已有有效本地缓存；点桌面至首个可交互大厅，不等待慢 GPU 探测；至少 20 次，p95≤3 秒 |
| 首屏目录 | 参考网络与冷/热缓存分列；请求发出至可操作首屏，至少 20 次 p95≤2 秒；另报无缓存首次安装与失败率 |
| 目录可用性 | 月度目标 99.5%；有效请求中成功 2xx/合理 304；服务错误/超时计失败，用户取消单列；只剔除提前公告的维护窗口并同时报告原始口径 |
| 大文件 | ≥10 GiB 自造归档、≥40000 小文件，跨中断继续；流式内存不随包大小线性增长，空间计算与实际分配对账 |
| 正式游戏验证 | 精确组合下连续 ≥30 分钟真实操作，含冷热路径、战斗/移动等代表场景、输入/音频、保存与重启实际读档，无阻断缺陷 |
| 30 FPS 目标内容 | 平均≥27 FPS，帧时间 p95≤50ms，1% low≥20 FPS，游戏逻辑速度 0.95～1.05 倍 |
| 60 FPS 目标内容 | 平均≥54 FPS，帧时间 p95≤25ms，1% low≥40 FPS，游戏逻辑速度 0.95～1.05 倍 |
| 多次切换 | A→大厅→B→大厅→A 至少五轮；每次旧 PID/窗口/音频/输入释放，资源不持续累积，存档正确 |

帧时间从实际呈现时点计算，平均 FPS 用实际帧数/测量时间；p95 使用排序后 `ceil(0.95*n)` 位，1% low=`1000 / 最慢 ceil(0.01*n) 个有效帧间隔的平均毫秒数`。报告总时长/帧数、加载区间及排除理由；只允许预先声明的非交互加载段单列，游戏内卡顿不能删除。游戏速度基于可验证游戏时钟/逻辑事件，不能仅用渲染 FPS 推断。

设备记录 SoC/RAM/OS/App/slot/core/profile/内容/驱动/page size、渲染分辨率、画质、输入、温度/供电和散热条件；性能 overlay、降频和后台负载说明。未测的声音、输入、读档或长时稳定性不能随“已出画面”通过。当前 BotW 约 7～13 FPS、实际重载未验证，仍是实验运行，不能据本文升级为 verified。

## 7. 阶段门槛与阻断项

G0 通过后才大规模铺设界面：两款真实游戏、唯一模块、同 APK/独立进程、显式根、正常/崩溃退出不杀大厅、各自保存且重开读档，执行加载与页大小声明有证据。G1 从干净候选安装经真实服务下载闭环；G2 全部 P0 可靠性/权限/恢复；G3 发布候选包含正式内容范围、签名/许可、设备性能和运行保障。阶段与 T-01～24 依赖详见计划。

下列问题直接阻断对应放行：丢已提交档、跨游戏污染、启动半包/未验签程序、越权公开内容、默认上传诊断/密钥泄露、native 退出杀大厅、协议篡改被接受、核心流程无恢复出口。非阻断视觉问题可单列计划，但不得把缺失主流程写成“仅 UI 待优化”。P1 只有通过范围变更进入当前版本才成为交付要求，不为凑“完整”默认扩张支付/云游戏等。

## 8. 验收记录模板

每条结果保存：case_id、requirement_ids/subrule_ids、App commit/version/cert/build、slot/core/profile/driver/content、设备匿名测试编号/OS/能力、前置数据、网络/空间、操作步骤、expected/actual、pass/fail/blocked/not_run、时间/执行人、脱敏证据 URI、缺陷和重测关联。记录可用 JSON/Markdown，不能只写“测试通过”一句。

签名/契约示例仅使用虚构内容和临时测试密钥，私钥不落库。大文件测试数据可本机生成并忽略；实际游戏/密钥/玩家存档不加入测试仓库。运行报告和日志遵守路径、隐私及浏览器清理要求。

本套文档提供 [只读基线校验器](verify_baseline.py) 和 [校验记录](data/baseline-review.json)，检验规范引用、需求追踪、Schema/OpenAPI、样例与负例。后续实现需另跑与改动有关的测试和真机案例，不能引用本次文档校验代替 G0～G3。
